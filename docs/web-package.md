# 로컬 웹 패키지

이 패키지는 검증된 웹 빌드를 폴더와 ZIP으로 전달하기 위한 도구입니다. 공개 사이트에 게시하거나 원격 서버에 배포하지 않습니다. 별도의 앱 설치기나 Node 실행 파일을 포함하지 않습니다.

## 실행

Node.js **24.19.0 이상**이 준비되어 있어야 합니다. ZIP 전체를 한 폴더에 풀고 `WindowsRun.cmd`를 실행한 다음 브라우저에서 **http://127.0.0.1:5315/** 를 여세요. 실행 창은 열어 두며, 종료할 때 Ctrl+C를 누릅니다. 다른 운영체제에서도 압축을 푼 폴더에서 `node serve-web.mjs`로 실행할 수 있습니다. 실행 시 npm이나 추가 패키지 설치는 필요하지 않습니다.

`web/index.html`을 직접 더블 클릭해 열면 안 됩니다. 파일 URL은 루트 기준 리소스 경로와 서비스 워커를 정상적으로 제공하지 않습니다. 서버는 `web/`를 HTTP 루트로 제공하므로 기존 `/assets/`, `/manifest.json`, `/sw.js` 경로를 그대로 사용합니다. 브라우저는 자동으로 실행하지 않습니다.

서버 주소는 `127.0.0.1:5315`로 고정되어 다른 기기에서 접속할 수 없습니다. 포트가 이미 사용 중이면 다른 포트를 임의로 선택하지 않고 종료합니다. 브라우저 저장 데이터는 이 주소에 속하며, 파일을 교체하기 전에 게임 설정의 현재 진행 다운로드를 사용하세요. 같은 주소를 사용하는 다른 패키지를 동시에 실행하지 마세요. 온라인 기능은 원래 빌드의 Firebase 설정과 네트워크 상태에 따릅니다.

## 제작 순서

1. 최종 소스 변경을 커밋합니다.
2. 해당 커밋에서 기존 웹 빌드와 검증 절차를 완료합니다. 패키징 도구 자체는 빌드·테스트를 대신 수행하지 않습니다.
3. 저장소 루트에서 `node scripts/package-web.mjs --check`로 파일 참조와 라이선스 수집, ZIP 생성 가능 여부를 확인합니다. 이 모드는 ZIP과 release 파일을 쓰지 않으며, 작업 중인 소스에서도 사용할 수 있습니다.
4. 최종 검증 후 `node scripts/package-web.mjs`를 실행합니다. 추적 중인 변경이 남거나 `dist`의 마지막 수정 시각이 현재 커밋보다 오래되면 중단합니다.

버전은 `package.json`에서 읽습니다. 현재 버전의 결과는 다음 두 파일입니다.

- `release/Stock-Trading-Game-1.15.0-web.zip`
- `release/Stock-Trading-Game-1.15.0-web.zip.sha256`

ZIP에는 `web/` 전체, `WindowsRun.cmd`, Node 기본 모듈만 사용하는 `serve-web.mjs`, 한국어 `README.txt`, `THIRD-PARTY-NOTICES.txt`, `PACKAGE-METADATA.json`이 들어갑니다. 원본 `dist`는 수정하지 않습니다. 재귀 삭제는 수행하지 않으며, 결과 파일은 저장소의 실제 `release` 폴더 안에서 임시 파일 작성 후 이름을 바꿔 교체합니다. 파일 교체가 실패하면 임시 파일이 남을 수 있습니다.

## 무결성과 재현

메타데이터는 버전, 소스 브랜치·커밋, Node 버전, 빌드 시각, 의존성 이름·버전·고지문 경로, 각 파일의 크기와 SHA-256을 기록합니다. 자기 자신을 포함한 해시는 만들 수 없으므로 메타데이터 파일만 내부 파일 목록에서 제외하고, ZIP 옆 SHA-256 파일이 메타데이터를 포함한 전체 압축 파일을 검증합니다. 소스 커밋 기록은 빌드 provenance의 독립적인 증명이 아니므로, 제작자는 위 순서에서 해당 커밋의 빌드와 검증을 직접 완료해야 합니다.

기본 빌드 시각은 `dist` 파일 중 마지막 수정 시각을 UTC 초 단위로 기록합니다. 재현 가능한 빌드 파이프라인에서는 `SOURCE_DATE_EPOCH`에 해당 빌드의 UTC Unix 초를 지정할 수 있습니다. 동일한 소스 커밋·브랜치, 입력 파일과 의존성, Node 버전, `SOURCE_DATE_EPOCH`를 사용하면 정렬된 파일 순서·동일한 ZIP 시각·고정 압축 설정으로 동일한 ZIP을 만듭니다. 다른 Node/zlib 버전 간 압축 바이트 일치는 보장하지 않습니다.

PowerShell에서 전체 파일의 해시를 확인하려면 `Get-FileHash .\release\Stock-Trading-Game-1.15.0-web.zip -Algorithm SHA256` 결과를 `.sha256` 내용과 비교합니다.

## 라이선스와 서버 동작

라이선스 목록은 설치된 운영 의존성과 그 하위 의존성을 보수적으로 수집하며, 실제 번들에서 제거된 패키지도 포함할 수 있습니다. Vite가 생성하는 브라우저 보조 코드의 라이선스도 포함합니다. `node_modules`의 LICENSE·COPYING·NOTICE 파일을 원문 그대로 모읍니다. 별도 라이선스 파일을 배포하지 않는 Firebase 패키지는 소스의 저작권·라이선스 고지문을 모으고, 설치된 Apache-2.0 의존성의 전체 라이선스 문구를 함께 싣습니다. 고지문을 확보하지 못한 패키지는 조용히 누락하지 않고 패키징을 중단합니다. 이 목록은 앱 자체에 새 라이선스를 부여하지 않습니다.

서버는 GET·HEAD만 지원합니다. 원시 요청 경로를 먼저 검사해 상위 경로·숨김 파일·Windows 경로 표기·잘못된 URL 인코딩을 거부하고, 실제 파일 경로도 웹 루트 안인지 확인합니다. 쿼리는 파일 경로에서 분리합니다. 확장자가 없는 HTML 탐색 요청만 SPA의 `index.html`로 돌리며, 없는 JS·CSS·이미지는 404를 반환합니다. JS·CSS·JSON·이미지·글꼴 MIME을 지정하고 서비스 워커 범위를 `/`로 유지합니다.

HTTP 응답은 `no-store`이므로 ZIP 업데이트 때 HTML·JS·서비스 워커가 서버 캐시 때문에 낡은 내용으로 남지 않습니다. 서비스 워커가 따로 관리하는 오프라인 캐시는 웹 빌드의 revision 정책을 그대로 따릅니다. 패키징 도구는 저장 데이터나 서비스 워커를 임의로 지우지 않습니다.
